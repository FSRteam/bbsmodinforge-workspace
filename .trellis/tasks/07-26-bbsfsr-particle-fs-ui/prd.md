# PRD: BBSFSR 粒子界面 FS 化

## 目标

改善 BBSFSR 粒子动画编辑界面的整体观感与操作效率，使其视觉层级、控件风格和模式切换方式向 FS 粒子界面靠拢，同时保留 BBSFSR 更合适的输入交互。

## 已确认需求

- 粒子界面的整体视觉方向向 FS 靠拢，包括控件外观、间距、状态反馈和图标表达。
- 将原本需要通过多个按钮反复切换的模式，改造成接近 FS 的常驻可视化按钮组，使当前模式和可选模式更容易识别与切换。
- 输入框不移植 FS 的独立输入窗口/弹出式输入交互，继续使用 BBSFSR 当前的内嵌输入逻辑。
- 输入框需要吸收 FS 的成功设计：显示左侧语义图标，并更新输入框外观，使图标、文本、边框与状态反馈形成一致的控件。
- 计划完成后直接进入实现，不再等待二次确认。

## 约束

- 保持 BBSFSR 现有粒子数据模型、序列化格式和运行时语义不变。
- 不引入 FS 的输入框窗口设计。
- 优先复用项目现有 theme v2、图标 atlas、圆角和动效能力，不新增平行的硬编码视觉体系。
- 非 Refreshed/dark 等既有主题必须有合理回退，避免把某一主题的外观硬编码到所有主题。
- 改动仅限粒子编辑相关界面及必要的通用控件扩展；通用扩展不得破坏其他编辑器。

## 已确认事实

- 当前 `new/` 保留 FSR 扩展粒子运行时和标签页式编辑器，不能直接用 FS 粒子面板覆盖。
- FS 提交 `93ba4a2c` 的可视化模式切换由现成的 `UIIcons` 完成；该控件已经存在于 `new/`，但粒子分区仍大量使用 `UICirculate`。
- FS 提交 `c7bf6544` 的表达式表面由 `UIMolangExpression` 提供左侧语义图标、分隔色条和代码预览，但点击会打开独立 MoLang 编辑窗口。
- 当前 FSR 使用可直接编辑的 `UITextbox`，因此应保留输入事件、撤销边界和解析回调，只移植 FS 的视觉表达。
- FSR 比 FS 多出手动发射、全纹理、叠加材质、自定义形状、11 种朝向、碰撞外观和事件节点等模式，必须为这些扩展补齐图标，而不是退回文字循环按钮。

## 验收标准

- [ ] 粒子界面的主要模式以带图标、可见选中态的按钮组呈现，用户不必通过隐藏状态或循环按钮判断当前模式。
- [ ] 模式按钮切换仍驱动原有状态与数据路径，不改变存档结果。
- [ ] 目标输入框左侧显示与字段语义匹配的图标，输入框外观与 FS 方向一致，但编辑仍在原界面内完成。
- [ ] 普通资源 ID、日志和声音名等非表达式字段不被误标为 MoLang；只对表达式字段使用代码/轴向/时间等语义图标。
- [ ] hover、pressed、active、disabled、focus 等状态在启用相关主题能力时清晰可辨。
- [ ] 界面在常用尺寸下不发生文字、图标、输入框或按钮重叠。
- [ ] 切换回兼容主题时不出现功能回归；相关自动化检查通过。
- [ ] FSR 独有的模式也有可见图标与 tooltip，且所有选择值与原枚举/组件索引一一对应。
- [ ] 粒子 JSON 的读写结果和粒子运行时测试保持不变。

## 暂不包含

- FS 粒子系统的数据模型或运行时实现迁移。
- FS 的输入框窗口/弹出式输入流程。
- 用 FS 的 `UIDockLayout` 覆盖当前粒子标签页、布局预设或撤销系统。
- 与粒子编辑器无关的全局布局重构。
