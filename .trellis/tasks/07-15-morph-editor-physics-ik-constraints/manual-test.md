# 游戏内复测矩阵

使用同一个包含明显长骨链的模型，分别配置世界风、局部风、重力、IK 目标和窄角度骨骼限制。

## 1. 编辑器相机隔离

1. 在伪装编辑器中让模型和 IK/物理目标保持不动。
2. 连续绕模型旋转相机，再上下/左右平移相机。
3. 预期：世界重力和世界风方向不随相机旋转；平移相机不产生甩动或额外加速度。
4. 切换为局部风并旋转模型本身。
5. 预期：局部风随模型旋转，仍不随相机旋转。

## 2. 退出界面与多实例隔离

1. 世界中放置至少两个使用同一模型资源、但为不同表单实例的物理模型。
2. 玩家先静止，再快速移动/急停，同时打开和关闭伪装编辑器。
3. 预期：每个模型只响应自身宿主运动；不会同时继承玩家/摄像机的共同加速度。
4. 编辑一个仍在世界中可见的模型方块。
5. 预期：编辑器预览的重置/运动不会踢动或重置世界中的模型方块物理。

## 3. IK、物理与约束组合

逐项测试 constraints only、IK only、physics only、IK+constraints、physics+constraints、IK+physics+constraints。

- IK+constraints：IK 仍追踪目标，受限关节停在 min/max 内，而不是整条 IK 静止。
- physics+constraints：链仍受重力/风驱动，受限关节不越界。
- 三者组合：IK 先形成目标姿态，物理在其上产生动态，限制不清除最终程序姿态。
- 关闭 constraints：IK/physics 行为恢复为原有无限制结果。

## 4. 嵌套与渲染路径

1. 把带 IK/物理的模型作为带 transform 的 body part。
2. 分别在世界实体、影片预览、模型方块、物品/缩略图路径查看。
3. 预期：body-part transform 在渲染与模拟中一致；任何路径都不随主相机产生非预期位移、旋转或惯性。

## 5. IK 完全伸直与回正区间

1. 新建一条两骨 IK 链，保持 softness 缺省为 0，把目标沿链方向缓慢拉到链长之外。
2. 预期：链能到达精确全长，不再始终保留细小弯曲；组衔接处没有由 soft reach 造成的永久短缺。
3. 将 softness 显式设为大于 0，再重复拉伸。
4. 预期：只有显式 soft IK 保留渐近接近全长的效果，旧的显式数值不会被覆盖。
5. 不使用 pole，让目标反复经过接近全伸直的位置；重点停在预测弯曲角 0°、2°、3°、4°，并分别从链的两侧越过直线方向。
6. 预期：0°/2°/3° 时两段中心线严格共线，关节局部角回到模型原始直线角度，不向限制角度的反方向多偏；4° 时才恢复正常弯曲。bend side 在 20° 前继续保持稳定，不发生膝/肘翻面或抖动。
7. 再启用 pole、pole angle 和骨骼限制重复第 5 步。
8. 预期：显式 pole 仍拥有方向优先级，限制仍生效，穿越奇异区间没有突然翻面。
9. 使用截图中的同一模型与同一窄角度/零下限约束，打开骨骼线显示，把链拉到完全伸直并从限制边界内外缓慢往返。
10. 预期：骨骼线与网格关节一致；最终网格不会在线已共线时仍向限制反方向偏出一点。若目标因硬限制不可达，应保留少量目标误差而不是突破限制。

## 6. 性能对照

1. 使用同一模型制作多条 IK 链和多条物理链，记录修改前后相同视角、相同实体数量下的帧时间与 1% low；测试前先静置数秒完成预热。
2. 分别测试 IK only、physics only、IK+physics+constraints，并保持相同的 physics iterations、碰撞、风、固定步长和实体数量。
3. 预期：预热后不再逐帧复制/排序 IK 链、创建 wanted/chain-id 集合、pivot-frame map、chain-frame list 或 stiffness 数组；帧时间和 GC 尖峰明显下降。
4. 快速切换两个使用同一模型资源的表单，再关闭其中一个编辑器预览。
5. 预期：workspace 与 bend history 仍按 renderer/模拟所有者隔离；性能优化不重新引入跨模型状态污染。

## 7. 视口骨骼选择与属性同步

1. 关闭 IK/物理调试显示，依次打开 IK、物理、骨骼限制面板，在视口中点击三个不同骨骼。
2. 预期：当前面板的骨骼列表立即选中并滚动到被点击项，右侧字段显示该骨骼的数据，不切回姿态面板。
3. 开启 IK，只给其中两三个骨骼配置 IK；交替点击已绑定与未绑定骨骼的可见模型表面。
4. 预期：两类骨骼都解析到真实骨骼并更新当前面板；不得只有 IK 目标/链上的骨骼能点。
5. 打开 IK target/pole 和 physics attach 调试标记，分别点击普通模型表面与标记。
6. 预期：标记只追加其对应骨骼的拾取区域，不改变、遮蔽或错位普通骨骼 ID。
7. 在三个面板中分别按住 Ctrl 点击骨骼。
8. 预期：仍更新当前程序骨骼面板，不改变隐藏姿态面板的多选状态。
9. 使用 cubic VAO、含 CPU immediate/shape key 的 cubic 模型与 BOBJ 蒙皮模型各重复一次。
10. 预期：三种渲染路径行为一致；多表单和 body part 同屏时 ID 不串到其他表单。
11. 使用至少 20 根可见骨骼的模型，从骨骼顺序的前 20 根依次点击，并观察是否意外进入移动、缩放、旋转、trackball、view、screen 或 scale-all 操作。
12. 预期：只有实际点击 gizmo 可见句柄才启动 gizmo；所有普通骨骼点击都切换当前 IK/物理/限制面板选中项。

## 8. IK maintain-offset 与预弯原姿态

1. 使用此前能稳定复现问题的同一只手臂：FK 动画中肘部有轻微预弯，target、pole 与 `Pole Angle=0` 保持绑定时的位置和旋转。
2. 开启 IK 后停住控制器，并继续播放包含手臂动作的 FK 动画。
3. 预期：开启瞬间手臂完全不跳，肘部不被 pole 强行扭到另一个平面；后续每帧仍跟随原 FK 动画，不冻结在首次绑定姿态。
4. 只移动 target，不移动 pole；随后把 target 放回绑定位置。
5. 预期：手臂从本帧 FK 末端加上 target 相对绑定位移后求解；target 回位时恢复当帧 FK，而不是恢复一张静态快照。
6. target 保持不动，只将 pole 绕肩到目标轴移动约 10°，再把 `Pole Angle` 设为 5°。
7. 预期：肘部平面先相对旋转约 10°，再附加约 5°；pole 原位与 `Pole Angle=0` 时不改变 FK。
8. 启用 tip rotation，只旋转 target 控制器后再旋回绑定旋转。
9. 预期：末端只叠加控制器相对绑定旋转；旋回后恢复本帧 FK 末端旋转。
10. 分别测试 IK weight 0→1、影片绝对 target/pole override 淡入淡出、窄角度 constraints、完全直链和带 softness 的链。
11. 预期：weight=0/禁用后再次启用会重新绑定；绝对 target 在权重 1 精确命中；约束仍钳制最终旋转；直链只借 pole 选择弯曲侧，不在零输入时自行制造弯曲。
