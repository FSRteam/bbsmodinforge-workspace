# 伪装编辑器物理 IK 与骨骼约束系统性修复

## Goal

从坐标空间、运行时状态所有权和骨骼求解阶段三个底层边界出发，系统修复伪装编辑界面中的物理骨链、IK 链与骨骼约束互相污染或互斥的问题，并防止此前“伪装跟随玩家/摄像机移动”这一类观察者状态泄漏再次出现。

## Confirmed Facts

- 物理骨骼的重力方向和风方向当前会随编辑器摄像机方向改变。
- 退出伪装编辑界面后，其他模型的物理加速度会继承玩家的运动状态。
- 启用骨骼限制后，IK 直接失效。
- 历史会话已出现同类边界错误：渲染或模拟路径把 Minecraft 主相机/玩家状态用于本应由当前 `FormRenderingContext` 或模型实例拥有的状态，导致伪装、粒子等内容随观察者变化。
- FS 1.21.1 参考实现的 `FormRenderingContext.world` 独立保存实体绝对世界变换，并随表单、身体部件和模型的局部变换一起推进；迁移到 `new` 时这条矩阵链被遗漏，`ModelFormRenderer` 改用摄像机相对渲染矩阵作为物理 `baseTransform`。
- 当前求解顺序为 IK → 物理 → 最终骨骼限制。IK 的多骨链结果写入组合四元数 `orient`，最终骨骼限制随后把 `orient` 清空并回退到 Euler 值，因此会直接抹掉 IK 结果；IK 与物理求解器本身已能接收骨骼限制。
- 当前物理历史是静态全局缓存，按 `IEntity + modelId` 归属；同一实体上复用同一模型资源但使用不同表单/物理配置时会共享历史，归属粒度不足。
- 当前 Blender IK 重构后的 `ModelIKApplier` 有 54 个显式热路径分配点，旧 BBSFS 同文件仅 11 个；每条链每次渲染还会重复排序、构建 wanted 集合、帧表并遍历骨架。
- 物理运行时每次渲染重复构造全链 wanted/chain-id 集合、帧表和 chain-frame 列表；这些数据大多是编译期拓扑或可按模拟实例复用的 scratch。
- `IKSolver` 已允许 `REACH_LIMIT=1`，但新链默认 `softness=0.05` 会让有效长度渐近全长而不真正到达全伸展；这会继续表现为组衔接伸不直。
- 原 FS 历史提交 `878fd4b2` 曾实现 20° hysteresis / 3° singularity 区间保存弯曲法线，后续 Blender 重构移除了该状态；当前仅用单帧 rest/live bend fallback，缺少跨帧回正滞回。
- 2026-07-16 游戏内截图进一步确认：上一轮恢复的 3°/20° 逻辑只稳定了弯曲平面的方向，没有把两骨解析解的弯曲幅度归零；目标落在近直线区间时，链中心线看似共线，但局部关节旋转仍可能越过 authored straight/original angle，向限制允许方向的反侧留下一个小负角。
- 2026-07-16 游戏内再次复测确认：即使两段位置解已被钉为精确共线，网格关节仍会过角。根因是约束搜索用 `fromToMirroredX(restDir, segmentDir)` 评估仅含骨段方向的局部 Euler，而最终渲染写入的是 `orientMirroredX(...)` 生成的完整 swing+roll 四元数；bend-normal roll 可让最终 `orient` 越过约束，位置骨线却仍保持直线。
- 2026-07-17 用户澄清另一类独立问题：角色手臂/腿在绑定前已有轻微预弯，用来粗略定义以后 IK 的弯曲侧；启用 BBS IK 后当前实现会立即把关节旋转到 pole/弯曲提示的绝对平面，导致控制器尚未移动时模型已经偏离绑定前姿态。
- 本次不能只对三个症状打补丁，还要审查同一数据流中可由相机、玩家、编辑器预览或其他模型实例造成的隐式耦合。

## Requirements

- 重力和风必须先有明确的语义空间，再在单一边界转换到物理求解空间；旋转摄像机不得改变世界空间重力/风的实际方向。
- 每个模型/伪装实例必须拥有独立的物理运行时状态；玩家速度、编辑器预览运动和其他模型的上一帧状态不得在退出界面后泄漏。
- 编辑器的打开、切换模型、重载模型和关闭流程必须成对初始化/清理临时模拟上下文，不得修改全局或可跨实例复用的默认状态。
- IK 与骨骼限制必须按明确、可组合的求解阶段执行；启用合法限制时 IK 仍应工作，并把结果约束到允许范围，而不是被整段跳过或覆盖。
- 审查物理骨链、IK、骨骼限制、模型矩阵/相机矩阵和宿主实体运动的完整数据流，修复发现的同根问题。
- 保持现有模型数据格式兼容，不要求用户重建已有 IK、物理骨链或骨骼限制配置。
- 将此次根因与不可违反的坐标/状态边界记录进 Trellis 项目规范，作为后续相关修改的检查项。
- IK 与物理常规渲染不得按“链数 × 帧数”持续制造大量临时集合、帧对象、向量和四元数；拓扑数据在配置编译时缓存，可变 scratch 按 renderer/模拟所有者复用。
- 性能优化不得通过降低用户配置的迭代次数、破坏固定步长确定性或关闭约束/碰撞来换取。
- 默认 IK 必须允许链完全伸直；用户显式设置 softness 时仍保留 soft IK 行为和旧数据兼容。
- 接近直链奇异点时必须有稳定的回正/滞回区间，优先采用模型 rest bend，避免微弯、翻面和离开/进入奇异区间时的抖动。
- 两骨链进入直线恢复区间时，不仅要稳定 bend normal，还必须把解析位置解钉为精确共线，使关节局部旋转回到模型 authored straight/original angle；不得越过该角度在限制反方向产生小折角。这个小区间允许存在可控的目标位置死区，不能用反向过角换取数学上的逐像素追踪。
- 约束必须检查并钳制最终实际交给渲染器的局部 `orient` 四元数，而不只是位置求解阶段由骨段方向推导出的近似 Euler；受限结果必须继续推进父骨世界旋转，保证所有子骨按渲染器真实坐标系分解。
- 伪装编辑器视口拾取骨骼时，当前可见的 IK、物理或骨骼限制面板必须优先接收选择，并同步列表、滚动位置与属性字段；不得只更新隐藏的姿态编辑器选择。
- 普通模型几何、IK 目标、pole 与物理 attach 标记必须共享同一个无冲突拾取 ID 空间；开启或关闭任何调试效果不得改变普通骨骼是否可拾取。
- Gizmo 的 move/scale/rotate/trackball/view/screen 全部句柄 ID 必须形成完整保留区；任何表单或骨骼 ID 都必须从 `Gizmo.STENCIL_MAX + 1` 开始，不能沿用只覆盖旧移动轴的常量 7。
- IK 的绑定参考姿态与弯曲方向提示必须是两个独立量：参考姿态决定控制器未产生位移时的原始关节角，bend/pole 只消除后续求解的弯曲侧歧义，不能在绑定瞬间自行制造新的弯曲幅度或平面偏移。
- 已确认：IK 启用后，只要目标控制器的位置与旋转相对绑定输入未变化，整条链必须与进入 IK 前的 FK 姿态一致；系统应自动校准 pole 相对该姿态的角度偏移，用户不需要手动反复调 Pole Angle 来消除绑定跳变。
- 已确认：绑定参考不是一次性静态快照，而是每帧动画/FK 求值后的当前链姿态。目标与 pole 没有额外控制变化时，IK 不得压掉或冻结原动画。
- 已确认：pole 在自动校准后仍是精确、可动画的平面控制器；它相对本帧绑定基准的额外移动才旋转肘/膝平面，保持基准位置时不改变 FK 姿态。
- 已确认：现有 `poleAngle` 保留，并在自动绑定校准之后作为附加相对旋转叠加；默认 0° 不产生绑定跳变。

## Acceptance Criteria

- [ ] 在伪装编辑器中保持模型姿态不变、只旋转/平移摄像机时，重力与风造成的骨骼运动方向不变。
- [ ] 玩家静止、匀速和突然移动后退出编辑器，世界中已有与新出现的多个模型均只使用各自宿主运动/自身历史计算惯性，不继承玩家或编辑器预览加速度。
- [ ] 两个及以上模型同时渲染/更新时，暂停、重置或销毁其中一个模型不会改变另一个模型的物理状态。
- [ ] 同一骨链同时启用 IK 与合法骨骼限制时，IK 目标仍被求解，最终关节角被限制在配置范围内；关闭限制后行为与原有 IK 一致。
- [ ] 单独启用 IK、单独启用物理骨链、单独启用骨骼限制以及三者常见组合均无明显回归或求解结果被后续阶段意外覆盖。
- [ ] 世界实体、影片/伪装编辑器预览和其他现有模型渲染路径不再因当前主相机或玩家变换而产生非预期位移、旋转、重力、风或惯性变化。
- [ ] 相关编译、静态检查和可自动化回归测试通过；无法自动化的编辑器/世界场景给出明确的游戏内复测步骤。
- [ ] Trellis 规范记录模型模拟的坐标空间、实例状态所有权、生命周期清理和求解顺序不变量。
- [ ] 典型两骨 IK 与多链模型连续渲染时，链编译排序/wanted 集合不再逐帧重建，pivot frame 与求解 scratch 在预热后复用。
- [ ] 多条物理链连续渲染时，拓扑集合与 chain-frame 容器不再逐帧分配，原固定步长、约束、碰撞和风行为保持。
- [ ] softness 未显式配置的新/旧 IK 链可以完全伸直；显式 softness > 0 的配置仍保持渐近 soft reach。
- [ ] IK 链进入接近伸直的奇异区间时稳定回到/保持模型 rest bend 方向，越过区间不会突然翻面，离开区间后恢复正常 pole/目标控制。
- [ ] 对 authored-straight 的典型两骨链，把目标放在预测弯曲角 0°、2°、3° 附近时，两个段的方向严格共线，子关节局部旋转回到原模型直线角度，不出现限制反方向的小负角；目标超过恢复区间后才重新产生正常弯曲。
- [ ] 同一场景启用窄角度/零下限约束后，最终 `orient` 转回 Euler 必须位于 min/max 内；骨骼调试线与实际模型网格不得出现“线已伸直、网格仍向限制反方向过角”的分离。
- [ ] 分别打开 IK、物理和骨骼限制面板，点击视口中的不同骨骼；当前面板应立即选中相同骨骼并显示其属性，Ctrl 点击也不得改到隐藏的姿态列表。
- [ ] IK 开启与关闭时逐一点击已绑定和未绑定骨骼；所有有可见模型表面的骨骼都必须解析到其真实名称，调试目标只可追加拾取项，不得替代普通模型拾取。
- [ ] 模型至少包含 20 根可见骨骼，逐一点击前 20 根；任何骨骼都不得被解释为 gizmo 的 scale/rotate/trackball/view/screen 句柄。

## Out of Scope

- 重新设计 IK、物理骨链或骨骼限制的用户界面与配置格式。
- 与上述根因无关的动画功能扩展或视觉效果调整。

## Open Questions

- 无阻塞问题。目标仓库为 `new/`；IK 采用 maintain-offset 绑定语义，实时 FK 为输出基准，控制器相对绑定变化为输入。
