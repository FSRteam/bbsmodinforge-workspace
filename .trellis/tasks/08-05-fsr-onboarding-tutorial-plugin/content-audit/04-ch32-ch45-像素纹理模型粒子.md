## 批次概览与最严重问题 Top5

整体评价：第六幕（ch32-38）教学主线清晰（画笔→图层→资源管理→配置→装备→摆放→总结），"认知步骤（无需操作）"的节奏设计合理；第七幕（ch39-45）"预设成品→核心概念→逐标签攻克→表达式曲线"的渐进路线是全教程目前最好的章节设计之一。但本批次的致命弱点是**大量 UI 控件名称与宿主真实文案对不上**（粒子编辑器尤其严重），以及**至少一处凭空捏造的命令**。玩家按文案操作时会反复"找不到教程说的东西"。

Top5：

1. **[D·重] ch37_s6/s7 教学的 `/mp remove` 命令不存在。** 已检索宿主源码 `BBSCommands.java`（第 102-171 行）：模型方块相关命令只有 `/bbs model_block play_state <coords> <state>` 和 `/bbs model_block refresh <range>`，且需要 OP 权限（bbs.admin，等级 2）；没有 remove/list/clear 子命令，全源码检索不到 `"mp"` 字面量。玩家照做必然失败。hint 里的 `/mp list`、`/mp clear` 同样不存在。
2. **[D·重] ch41_s3 教学找「加速度」字段，但粒子编辑器里没有叫这个的字段。** particles 域全部 217 条标签中 motion.* 只有：位置 / 位置阻力 / 初始速度 / 旋转系列 / 模式（动态/参数化）；唯一的"加速度"是「旋转加速度」。线性加速在 Snowstorm 里由「位置」字段的语义承担，UI 上不叫加速度。
3. **[D·重] ch41_s2 / ch42_s6 / ch44_s3 三次让玩家展开「粒子初始化」分区找 X/Y/Z 数值输入框——该分区实名「初始化表达式」（initialization.title），内容是 创建/更新 两个 Molang 文本框，不是数值框；X/Y/Z 的「初始速度」实际在「运动」分区（motion.position_speed）。**
4. **[D·中] ch40_s2 发射模式第三项写「爆发（Burst）」，宿主文案实为「手动」（snowstorm.rate.manual=手动）。** 同一分区实名「生成速率」而非「速率」。
5. **[A·系统] 全部涉键步骤零例外地违反 keybinds-verified.json 明文规则**（"_meta.tutorial_rule"：教程必须写「默认」二字并提示可去 设置→按键绑定 查看；F9 可打开键位清单）。ch32 五个工具键（B/E/F/V/X）全部按键先行于工具栏按钮，且无一处提示键位可改。

## 逐章分析

### ch32 像素画工具箱（7 步）

整体评价：六种入口（开面板→建纹理→画笔→橡皮→油漆桶→吸管/移动→换色）顺序合理，操作与讲解交替得当。主要问题是工具切换一律以按键为主引导，与"按钮优先"的写作规范相反；两条 hint 夹带内部机制名。

- **[A·轻] ch32_s3_brush_tool**：「按 **B** 键（或点击左侧工具栏 **画笔** 图标）→ …」— 键在前、按钮在后，顺序颠倒。ui-domains 已证工具栏按钮存在（`bbs.ui.textures.tools.brush`=画笔）。建议改为："点击左侧工具栏第一个 **画笔** 图标 → …（默认快捷键 B，可在设置→按键绑定修改）"。s4（E/橡皮擦）、s5（F/油漆桶）同款问题，改法相同。
- **[A·主] ch32_s6_eyedropper_move**：「…松开 Alt → 按 **V** 键切换到移动工具 → 拖动画布」— instruction 与台词均未给按钮替代路径，而 `bbs.ui.textures.tools.move`=「移动图层」图标就在同一工具栏。应先指图标再提 V 键。
- **[A·轻] ch32_s7_swap_colors**：「观察左下角颜色选择器的两个色块…→ 按 **X** 键」— X 键在 ui-domains/keybinds 中均未发现对应可点击交换按钮，属"仅快捷键"，不算强加；但该键易被改绑且文案标签还是错的「反色」（keys.swap=反色，hint 自己也承认），却没有任何「默认键位可改 / F9 自查」兜底话术。
- **[B] ch32_s6_eyedropper_move**：hint「移动工具一次拖动记录为一个 undo 步骤（moveUndoBefore 机制）」— `moveUndoBefore` 是源码内部字段名，普通玩家无需也不该看到。建议删括号内容或改为"一次拖动 = 一步撤销"。
- **[C·轻] ch32_s6_eyedropper_move**：一步塞进两个新工具（Alt 临时吸管 + 移动工具），且两者无逻辑关联。建议拆成两步或在标题明示"两个小工具"。
- **[D·轻·需实测] ch32_s1_open_textures_panel / ch32_s2_create_texture**：四个标签名（像素画/像素画图层/纹理/纹理列表）、面板图标「调色板」、「+ 添加纹理」「空白纹理」菜单项在 ui-domains.json 与 ui-inventory.json 中均检索不到对应文案。流程合理但措辞需进游戏逐字核对。
- 附注：s3/s4/s5 的选项名（笔刷尺寸/柔软度/积聚、橡皮擦独立不透明度）已获 `bbs.ui.textures.brush_*`、`eraser_opacity` 标签证实，准确。

整体评价：物理三件套（初速/重力/阻力）+ 颜色渐变的选题很好，但本章是控件名失配的重灾区——四步的核心字段名在真实 UI 中找不到或不在教程所说的位置。

- **[D·重] ch41_s2_initial_velocity**：「展开 **粒子初始化** 分区 → 找到 **初始速度**」— 见 Top5 第 3 条：「初始化表达式」分区里只有 Molang 文本框；X/Y/Z「初始速度」输入框在 **运动** 分区。改为"展开 **运动** 分区 → **初始速度** → Y 设 2.0"。（同样错误见 ch42_s6、ch44_s3。）
- **[D·中] ch41_s7_lighting**：「找到 **光照** 分区或开关 → 启用光照」— 实际字段名是 **发光**，位于「颜色和发光」分区内（lighting.lighting=发光）。玩家找"光照"会扑空；hint 的语义解释（关=全亮自发光）倒是对的。
- **[D·轻] ch41_s5_appearance_color**：「找到 **颜色 / 色调** 字段 → 点击颜色选择器」— 实际分区名「颜色和发光」，通道为 红色/绿色/蓝色/Alpha 滑块 + 实体/渐变/表达式模式；无「色调」，色轮式选择器亦未见诸文案。
- [D·轻·需实测] ch41_s6_gradient_color：「双击添加一个关键点」— 文案中有右键「添加颜色停止/移除颜色停止」（lighting.context.*），双击行为需确认，建议两种都写或按实测写。

### ch42 纹理与动画（7 步）

整体评价：UV→帧动画→循环/拉伸→旋转的进阶内容编排合理，「动画/帧数/动画帧率/循环/拉伸/初始旋转/初始旋转速度/广告牌大小」等关键词全部命中；问题是两处分区归属错位和 Molang 抢跑。

- **[C·中] ch42_s7_size_over_lifetime**：要求直接切「表达式」模式输入 `variable.particle_age * 0.05` — Molang 到 ch44_s1 才正式教，此处属于"用到后面才讲的 X"。建议本步只用「曲线」直觉演示（先大后小），表达式例子挪去 ch44_s2 之后；或在此先用一句白话解释变量含义。
- **[D·轻] ch42_s6_rotation**：「**运动** 标签 → **粒子初始化** 分区 → 初始旋转/旋转速度」— 字段名全对（motion.rotation_angle/rotation_speed ✓），但所属分区应为 **运动**，无「粒子初始化」分区（同 ch41_s2）。
- **[D·轻·需实测] ch42_s5_facing_mode**：「在 **外观与纹理** 标签找到 **摄像机朝向模式**」— 字段名与选项（朝向 XYZ/朝向 Y 轴/绕 XYZ 旋转/绕 Y 轴旋转 ✓ 全命中），但它挂在 snowstorm.general.*（常规分区，通常在文件标签）之下，是否真的出现在外观标签需实测确认。
- **[C·轻/D·轻] ch42_s2_uv_mapping**：「16x16 图集每格是 1/16 = 0.0625」要求新手当场心算小数，且「宽高根据图集尺寸设置」含糊。建议直接给常用值表或让玩家抄 0/0/0.25/0.25 这类具体数。
