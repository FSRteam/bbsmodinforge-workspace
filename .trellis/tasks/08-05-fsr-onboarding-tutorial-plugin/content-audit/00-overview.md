# 教程插件篇章内容审查 · 总评

> 审查日期：2026-08-22。对象：`chapters-*-skeleton.json` 全部 52 章 343 步（实际逐章逐步核对为 341 步）。
> 方法：6 个并行审查批次，每条问题均要求对照宿主真实 UI 文案（ui-domains.json）、键位清单（keybinds-verified.json）或宿主源码取证。
> 本目录只做分析与总结，**未修改任何教程内容文件**。

> **2026-08-23 更新**：本报告所列可落实问题已全部修复到骨架文件（ch24 整章重写、新增视频导出基础章，`_check.py` 0 错误），明细与遗留实测项见 [07-fixlog.md](07-fixlog.md)。宏观课程重排仍为待决事项。

## 一、总体判断

这套教程是一部质量不均匀的**交互式参考手册**，而不是合格的**新手引导**。

- 好的一面：绝大多数按钮/控件文案与宿主 `zh_cn.json` 逐字一致（各批次抽查合计 100+ 处几乎零捏造）；组合键位与 `keybinds-verified.json` 零偏差；部分章节（ch23/ch25/ch28/ch33/ch43/ch44）的"先踩坑后爬坑"设计是真正的人类学习路线。
- 问题的一面：52 章扩写时把自家教学法（`tutorial-script.json` _meta.pedagogy：「痛点先行、工具后置、早期成就感优先、每章只引入一个新概念」）**系统性反转了**——痛点不再先行，工具成批倾泻，首个真成品被推到第 22 章，而玩家最终目的（导出视频）从头到尾没有教学章。

## 二、最严重的发现 Top 10

按对读者的伤害程度排序：

1. **【路线】前 15 章全是伪装深水区**。IK 链（ch09-10）、物理骨链（ch11-12）、骨骼约束（ch13）这类绑骨高阶内容占全篇 29%（98 步），而影片编辑器 ch16 才开门。新手在第 9 章就被要求理解极向量与柔软度权重——这是给已经做出作品的人准备的精修课，不是 onboarding。
2. **【缺失】视频导出从未被教**。规划的 ch43（FFmpeg 配置排错）/ ch44（F4 手动与 F6 影片导出）/ ch45（导出参数）三章无交付物；实际 ch46 直接从"批量导出"冷启动，以「你已会 F6」的口吻出现。F4 全篇 0 次教学，F6 仅 2 处顺带提及。玩家学完 343 步仍然不知道怎么把自己的作品变成 mp4。
3. **【虚构】整章建立在不存在的产品上**。ch24「演员控制」教的"演员控制器 / 游戏手柄控制器 / 表达式控制器 / 控制器标签页"在源码与 UI 文案中零命中；回放编辑器实际只有 玩家/模型/姿势/IK/物理 五个标签页（UIReplaysEditor.java:142）。读者照做第一步就会找不到入口。
4. **【快捷键强加·系统性】** 用户点名的问题属实且普遍：有按钮可点的操作，教程优先教背快捷键。典型：ch03_s1 用全局键 B 打开伪装面板（绕过 ch01_s3 自己教过的面板按钮）；ch15_s5 反斜杠暂停（动画状态管理器有打开入口）；ch18_s2 Shift+T 插关键帧（hint 自己承认右键菜单更快）；ch19/ch20 数字键切标签（标签页本身可点击）；ch46_s6 按 F6 导出（摄像机编辑器有「录制视频」按钮）。正确写法应是**先指路按钮，再附赠快捷键**。
5. **【不可执行】多处照做必失败**：ch07-ch08 共 14 步依赖"选择/新建特殊形态"，但伪装面板右键菜单经核实无任何新建入口，形态从哪来全篇未交代（第 7 章第一步即卡死）；ch37_s6/s7 的 `/mp remove|list|clear` 命令不存在（源码只有 `/bbs model_block play_state|refresh` 且需 OP 权限）；ch41_s3 教找粒子「加速度」字段（UI 无此字段）；ch41/ch42/ch44 三处让玩家展开「粒子初始化」分区找数值框（实名是 Molang 文本框，初始速度在「运动」分区）。
6. **【语义讲反】ch29_s6** 把摇晃参数含义颠倒：源码中 摇晃=频率、摇晃强度=振幅，教程恰好写反，男版台词还引用了不存在的「摇晃频率」字段。
7. **【冲突】ch03_s3/ch04_s3** 让用户开着 Dashboard 按 F5 观察变身效果，与教程自己在 ch02 编制的按键冲突表（F5=切换调试）直接打架——读者按下去看到的是另一个东西。
8. **【前置倒挂】ch17/18/19** 从第 17 章起就教"插入关键帧""切到回放标签页"，但"回放"概念 ch22 才正式教；空影片按 I 是否有对象可插存疑。ch51 选择器缺命名实体前置，ch42_s7 Molang 表达式抢跑到粒子曲线之前。
9. **【开发者视角泄漏】** 源码路径、类名、内部机制名进入面向用户的文案：ch01 多步引用 `BBSModClient.java:976` 式出处、ch20_s4 写 "VECTOR3F_SCALE"、ch21r_s3 说"源码里写死了"、ch35_s1 出现英文源码注释、ch38_s3 引用 Keys.java 内部机制、多步 hint 泄漏内部锚点名（如 pose.context.fix）。
10. **【体量】343 步 ≈ 纯走完 3.5-4.5 小时、现实 5-8 小时**。游戏内教学行业基准是 10-30 分钟内让玩家完成第一个闭环。作为"onboarding"，本教程在体量上就劝退；作为参考手册又缺少检索结构。

## 四、规划文档自身的问题

- `chapter-plan.json`（52 章规划）、`story-outline.json`（八幕大纲）与实际 skeleton 三套账互相对不上：story-outline 自称六幕实为八幕；总步数出现 300/304/343 三个版本；自 ch19 起编号全面漂移；≥9 个规划章被静默删除（含整个导出基础段）。
- skeleton `_meta` 自定的「每章 1000+ 字、讲透每个按钮」目标与既定教学法「每章只引入一个新概念」互斥，前者在实际写作中胜出——这是 C 类问题的直接根源。
- 两个孤立的"章节总结"（ch38/ch45）出现在中段，其余阶段没有对应收束，结构不对称。

## 五、修复方向建议（仅建议，未动手）

1. **先补洞再谈顺序**：D 类中的虚构控件/命令（ch24 整章、/mp 命令、加速度字段、粒子初始化分区、运动路径拖拽、摇晃语义）必须以真机验证为准重写或删除。
2. **A 类批量整改规则**：凡同一操作既有按钮又有快捷键的步骤，统一改为「指出按钮位置与外观 → 让用户点击 → 附注熟练后可用快捷键 X（可按 F9 查实际绑定）」。涉及 ch03/ch05/ch06/ch15/ch17/ch18/ch19/ch20/ch22/ch32/ch46 等。
3. **课程重排（低成本三刀）**：
   - 第一刀：ch02 按键分类学整章降级为附录/F9 自查引导，把省出的位置给"第一次变身并保存"的完整成就感闭环；
   - 第二刀：ch09-13（IK 进阶/物理/约束）后移为进阶选修模块，入门段只保留 FK 与基础姿势；
   - 第三刀：新增/恢复"导出第一支视频"教学章，并把它提前到影片基础之后（目标：50 步内让新手导出第一支 10 秒 mp4）。
   - 详细七阶段里程碑方案见《06-课程结构总评.md》。
4. **统一规范**：所有键位一律标「默认」并附 F9 自查话术；禁止源码路径/类名进入用户可见文案（可挪入 hint 的开发备注字段）。
