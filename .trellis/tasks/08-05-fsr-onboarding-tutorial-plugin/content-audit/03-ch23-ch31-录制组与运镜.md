## 批次概览与最严重问题 Top5

**总体评价**：ch23、ch25、ch28 质量较好，绝大多数按钮文案、剪辑类型名、快捷键都能与宿主真实 UI 对上；ch29 的「图层叠加」教学设计（先踩坑再爬坑）是全批次亮点。但存在两类致命伤：一是 **ch24 整章建立在一个宿主中不存在的「演员控制器」功能上**（源码零命中）；二是多处 step 描述了**实际 UI 中不存在的交互**（拖动运动路径点、「从当前相机复制」右键菜单、眼睛图标、命名弹窗等）。另外「先按快捷键、后提按钮」的写法在含键步骤中仍是主流，与既定的「按钮优先」原则相悖。

整体评价：教学设计最佳的一章：故意让用户先体验「摇晃没效果」再爬坑，直击 _meta 里的 criticalFinding。层级官方文案逐字正确。问题是三个添加/调层快捷键全部以按键为主线（菜单替代品齐全），以及 s6 参数语义讲反。

问题清单：

- **[B轻] ch29_s1**｜原文：「每个剪辑在同一个 position 对象上依次施加效果」｜「position 对象」是源码视角说法，对普通玩家应说「同一个镜头状态/镜头数据」。
- **[A] ch29_s2**｜原文：「按 **Shift + A**（在光标位置添加剪辑）→ 选择 **摇晃**」｜可点击替代充分：右键时间线的「添加」子菜单里有「在光标处添加剪辑...」「在当前刻处添加剪辑...」「在选定剪辑上方添加剪辑...」（`UIClips.java:297-302`，label 与 keybinds-verified camera.add_* 三条一一对应），顶部还有「+ 添加剪辑」。应先教右键菜单。
- **[A] ch29_s3**｜原文：「按 **Alt + ↑**（上箭头）把图层从 0 改为 1」｜可点击替代：选中剪辑后右侧「层级、刻和持续时间」面板直接改「层级」数字。hint 里提了右键编辑改数字（好），但 instruction 主次颠倒；Alt+↑ 绑定本身 ✓（camera.clip_layer_up）。
- **[B轻] ch29_s4**｜原文：「**叠加型**（摇晃/平移/角度/阻力）在传入 position 上 += 分量」｜「+= 分量」程序口吻；分类知识本身与实现一致（shake additive；look/orbit/dolly_zoom overwrite）✓。
- **[A] ch29_s5**｜原文：「选中路径剪辑 → 按 **Shift + Alt + A**」｜同 s2：菜单项「在选定剪辑上方添加剪辑...」就是它的按钮形态，应菜单为主。绑定 ✓（camera.add_on_top）。
- **[D] ch29_s6**｜原文：「把 **摇晃** 从 0.1 拉到 1.0，**摇晃强度** 从 1.0 拉到 5.0」＋userWillSee「幅度变大（摇晃 1.0）、频率变快（强度 5.0）」｜语义颠倒（详见 Top5 #4）：摇晃=频率、强度=振幅；两字段默认都是 0；强度 5 会造成弧度级剧烈抖动，演示效果失控。hint「分别控制 X/Y/Z…抖动量」也不准确：分通道控制是「启用」位开关（active 位标志，7 通道含 FOV），各通道共享同一个强度值。男台词的「摇晃频率」字段不存在。
- 正面确认：s7 排查口诀（没效果先查图层）非常实用，保留。

## ch30_look_orbit_tracker：注视与跟随（8 步）

整体评价：看→轨道→追踪器的递进和三者对比总结不错；但看剪辑配置面板的三处控件名全部失真（选取目标/相对/朝前看 vs 教程的选择器/选择实体/朝运动矢量），s5 轨道演示按所写操作得不出承诺结果。

问题清单：

- **[B轻] ch30_s1**｜原文：「看剪辑是重写型：读入下层位置后完全重写角度」｜术语密度偏高，好在 s7 有对比表兜底；建议正文用大白话、括号给术语。
- **[D] ch30_s2**｜原文：「右侧配置面板显示：**选择器**（下拉：实体选择器/方块）、**选择实体...** 按钮…**朝运动矢量** 开关」｜实际 UILookClip 面板：目标 区块（按钮实名「**选取目标...**」CAMERA_PANELS_TARGET_TITLE）+「相对」开关；方块模式是独立区块「看向方块」开关 +「方块坐标」；运动矢量开关实名「**朝前看**」（forward，tooltip 正是过山车比喻）；另有「偏移」模块。Shift+Alt+A 用法继承 ch29 的 A 类问题。
- **[D] ch30_s3**｜原文：「点击 **选择实体...** → 在弹出的实体选择器里选择一个回放（或附近的生物）」｜按钮名不符（选取目标...）；弹窗列出的是影片中的演员实体（displayActors(controller.getEntities())），是否包含「附近的生物」存疑，需实测后再写。
- **[D轻/B] ch30_s3b**｜原文：「找到 **朝运动矢量** 开关（勾选框）」＋hint「它通过 applyUnderneath(context.ticks - 1) 读上一刻位置…」｜开关实名「朝前看」；hint 把内部方法名写给了用户（B）。
- **[D] ch30_s5**｜原文：「调整 **距离** 为 5.0、**偏航** 滑块从 0 拖到 360 → 把剪辑长度拉到 100 刻 → 播放」＋userWillSee「绕目标实体旋转一整圈」｜操作-结果不匹配：OrbitClip 的 yaw 是静态偏移量（applyClip 里 `this.yaw.get()`，360≡0），播放期间恒定，相机不会转圈；必须给偏航通道打关键帧（0 刻=0，100 刻=360）才会环绕——hint 自己说了偏航是关键帧轨道，instruction 却没教打关键帧。应补一步「在偏航轨道打两个关键帧」。
- 正面确认：s4/s6/s7 认知对比与选型指南（路径+看/轨道/追踪器）清晰实用；追踪器字段细节建议实测后再落文案。

## ch31_advanced_clips：程序化镜头（7 步）

整体评价：关键帧/数学/重映射三种剪辑都真实存在（UIKeyframeClip/UIMathClip/UIRemapperClip、ui-domains `clips.bbs:keyframe|math|remapper` ✓），「重映射=给下层时间轴变速」的概念讲解是亮点。但两个实操步骤都让相机飞到世界原点（X/Z 默认 0），新手会以为坏了；重映射的进入路径也与实际面板不符。

问题清单：

- **[D轻] ch31_s2**｜原文：「每条轨道可以右键 → **编辑轨道** 进入曲线图」｜交互细节未核实（UIKeyframeClip 的实际面板结构），标注待实测；「删除之前的剪辑」交代了清理前置 ✓ 好。
- **[D] ch31_s3**｜原文：「在 0 刻插入关键帧值 70.0 → 在 60 刻插入关键帧值 80.0 → 播放」＋userWillSee「其他通道保持默认值（X/Z=0…）」｜关键帧剪辑完全接管相机后 X/Z=0 意味着镜头飞到世界坐标原点附近，玩家多半站在几百格外，什么也看不到（甚至区块未加载）。缺前置：先把 X/Z 手动设为自己附近，或提示「请站到坐标 0,0 附近观察」。Y 70→80 也默认了海平面地形。
- **[D] ch31_s5**｜原文：「在 **Y** 通道输入框填写 `70 + sin(t * 0.1) * 5`」｜同 s3 的原点问题。数学本身对：sin(t*0.1) 周期 ≈62.8 刻 ✓，Y∈65~75 ✓。
- **[B] ch31_s6**｜原文：「这是 applyUnderneath 机制的典型用途」｜内部方法名写给用户；改为「它需要先算出下面图层的结果，所以必须放在更高层」即可。
- **[D轻] ch31_s7**｜原文：「右键重映射的 **重映射** 轨道 → **编辑轨道**」｜实际面板只有一个「**编辑关键帧**」按钮（CAMERA_PANELS_EDIT_KEYFRAMES，`UIRemapperClip.java:40-46`），点击进入内嵌曲线图再插关键帧；没有「右键轨道」这条路。0→120 映射产生 2 倍速的结论 ✓ 成立。
- 待实测：ch31_s4 数学剪辑变量清单（t/o/p/yaw/fov/velocity）未逐项核对，发布前需对照表达式实现确认。
