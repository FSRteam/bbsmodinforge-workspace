# new(bbs-FSR) 编辑器缺陷修复批次

## 概述

对 new(bbs-FSR) 独立仓库中六个客户端编辑器缺陷进行修复，涉及动画状态编辑器、实体选择器/3D 预览变换、摄像机编辑器及 MobForm 常规渲染。

每个缺陷对应一个独立子任务，可独立验证与回滚。父任务负责集成验收。

## 目标仓库

- **仓库**：`new/`（单分支跟随 FSRteam/bbs-FSR master）
- **基准分支**：`master`
- **工作分支**：从 `new/` 的 `master` 新建

## 缺陷清单

### 1. 动画状态编辑器 – 播放头渲染异常 (P2)
- **位置**：`UIAnimationStateKeyframes` / `UIAnimationStateEditor`
- **现象**：时间线轨道区域内播放头（cursor / tick marker）渲染异常，用户无法清晰辨识当前播放头位置
- **预期**：播放头在时间线区域以正确颜色、正确 Z 序可见地渲染，与其他编辑器（如影片剪辑时间线）的播放头渲染样式一致
- **风险**：仅 UI 渲染层，不涉及数据逻辑

### 2. 实体选择器 – MobForm 重复渲染与交互异常 (P1)
- **现象**：
  a) 为实体选择器添加相同 ID 的 MobForm 时，3D 预览区域上半部分出现该 MobForm 的额外重复渲染
  b) 重复渲染视角固定于模型底部，不跟随主视角旋转/平移
  c) 悬浮该重复区域触发拾取高亮但无法选中骨骼
- **附随问题**：
  d) Gizmo 在相同条件下选中肢体后未能自动跟随至所选肢体位置
- **预期**：无重复渲染；相同 ID 的 MobForm 不产生视觉或命中层面的重复实例

### 3. 3D 预览 G/S/R 变换 Y/Z 轴方向反转 (P1)
- **位置**：3D 预览中的 Modal Transform（按 G/S/R 后的鼠标拖动变换）
- **现象**：Y 轴与 Z 轴变换操作时数值变化方向与实际预期相反（反转），X 轴正常
- **预期**：Y 和 Z 轴变换方向符合直觉（与 Blender/Maya 等标准 DCC 工具一致的方向约定）
- **风险**：需检查所有共享同一变换代码的编辑器（Pose Editor、Model Editor、Film Editor）不产生回归

### 4. 摄像机编辑器 – 追踪器骨骼显示名不一致 (P2)
- **位置**：摄像机追踪器（tracker）的骨骼选取 UI
- **现象**：追踪器中「选取肢体」展示的骨骼名称显示为内部持久化 ID，而非 Pose 轨道及过滤轨道中使用的友好显示名称
- **预期**：三处（追踪器选取、Pose 轨道、过滤轨道）骨骼名称一致，均使用显示名称
- **风险**：仅 UI 字符串替换层

### 5. 摄像机编辑器 – 飞行模式速度残留 (P2)
- **位置**：`CameraController` / 飞行模式（fly mode）
- **现象**：WASD 移动摄像机后取消飞行模式，再次启用时摄像机沿上次移动方向持续自动飞行。需用户再次按 WASD 才恢复正常
- **预期**：取消飞行模式时 velocity 归零；重新启用时摄像机静止
- **风险**：仅状态重置，不涉及逻辑变更

### 6. MobForm 加色法混合模式适配 (P3)
- **位置**：MobForm 渲染管线
- **现象**：MobForm 遗漏对加色法（additive blending / 加色混合）的适配
- **预期**：MobForm 支持加色法渲染模式，与其他 Form 类型（如 Particle、Pose）的加色法行为一致
- **风险**：渲染管线混合模式变更需逐位等价验证

## 验收标准

1. 每个子任务通过其 `prd.md` 中定义的验收条件
2. 父任务集成验证：六个修复同时应用时无交互冲突
3. 验证测试通过：`compileClientJava` + 相关 test source sets
4. 工作分支提交至 `new/` PR 至 FSRteam/bbs-FSR master

## 非目标

- 不引入新功能，仅修复缺陷
- 不改动服务端代码
- 不改动 `forms` 数据模型序列化格式（除非加色法必需）
